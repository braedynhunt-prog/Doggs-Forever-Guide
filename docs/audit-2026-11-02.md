## Struck from the test lists (resolved)

### Guidelime (read from the installed 6.015 source, Interface 16001, "C:\Program Files (x86)\World of Warcraft\_forever_\Interface\AddOns\Guidelime")
- `[CI itemId,count]` and `[UI itemId]` are real tags: GuideParser.lua:80/82 define COLLECT_ITEM and USE_ITEM; CI sets step.manual=false (CurrentGuide.lua:222-224) so the step completes on bag count and shows "Name: n/qty"; UI makes a use-item button (ActionButtons.lua:406). The UI tag's optional second number is a target NPC id, not a count. Our usages parse.
- Quest titles: CurrentGuide.lua:513 uses the tag title first, then Questie's name, then the id; the unknown-quest popup fires only with dataSource "DB" (default is "QUESTIE", Guidelime.lua:131). Forever-new ids display their tag titles. (Strikes the Expanding Horizons / Making Do title test.)
- Skyborne: Data/Data.lua:13-14 has Skyborne (raceID 95) with classes Warrior, Hunter, Rogue, Druid, Mage, Shaman; D.applies checks UnitFactionGroup, so `[GA Alliance]`, `[A Druid]`, `[A Warrior]` show. Only the live UnitRace token ("Skyborne"?) is untested: `/run print(select(2,UnitRace("player")), UnitFactionGroup("player"))`.
- Zones: MapDB.lua:664-668 adds Zephras Isle (2521), Mount Hyjal, Darkspear Islands, Riverglades, Shen'dralas; Moonglade 1450, Dalaran 125 (Classic ids, Forever Dalaran has no separate entry). All 21 zone names in the three guides resolve. An unknown zone name shows the ZONE_NOT_FOUND popup.
- Tick reset: CurrentGuide.lua:265-270 calls matchUpdatedGuide when the step count changes; it re-keys progress by exact step text and drops only entries with no matching text. Ticks survive on unchanged lines. RULES.md corrected (was "wipes them").
