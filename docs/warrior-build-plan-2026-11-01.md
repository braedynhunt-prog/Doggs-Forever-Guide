# Skyborne Protection Warrior guide: build plan (parked 1 Nov 2026)

Status: **planned, approved, not started.** Braedyn asked how hard a warrior version of the guide would be, chose a Skyborne Protection Warrior for someone else, and parked execution ("I will do it later"). Nothing under `guide/`, `tooling/` or `weights/` was changed. The only artefact on disk is `compare/polestar-0.2.6/01-zephras-isle.guide` (untracked; see Phase 1).

## Decisions taken (1 Nov 2026)
- Separate addon **`guide/Guidelime_ForeverWarrior/`**, Guidelime group string **"Forever Warrior 1-30"**.
- **Generator-built**: the Alliance chapters stay the hand-written route source; a per-variant overlay plus generated gear calls produce the warrior folder. Later race/class combos then cost a weight profile and a class thread, not a rewrite.
- Gear policy: **1H + shield throughout** (tank set, mail). Professions: ~~Mining + Blacksmithing~~ **Skinning + Mining (decided 1 Nov 2026, evening)**, the same pair as the shaman: the Guard's mail set needs ~34 Shadowgem and ~22 Pristine Leather by 25 (see the Execution log), so it is not self-craftable without rare-drop farms. The set is an optional AH / later note, nothing in the route depends on it, and no Blacksmithing stops are planned. First Aid, Cooking, Fishing threads unchanged.
- Build from the datamine before launch, with an in-game test list for what the data cannot settle.
- The Skyborne race needs the paid Skyborne pack; assume the player has it.

## Design
### Source of truth and outputs
- Route source: `guide/Guidelime_ForeverAlliance/02..26_*.lua`, untouched.
- Variant folder `tooling/variants/skyborne_warrior/`:
  - `variant.json`: folder, group, class, race, chain, keep/drop tag words, ordered chapter list (`00s`, `00t`, `00u` new + `02`..`26` sources), TOC text, flag words.
  - `chapters/00s_ZephrasIsle1.lua`, `00t_ZephrasIsle2.lua`, `00u_DalaranToLochModan.lua`: hand-written, copied verbatim.
  - `overlay/<chapter>.txt`: edits anchored on a stable token of a route line (`QA<id>`, `QT<id>`, `QC<id>`, `TAR<id>`, `G<x>,<y>`, `N <title>`; `#n` for the nth match). Directives `@replace`, `@after`, `@before`, `@delete`, `@header`, `@gear-dungeon`; blocks end at the next `@`. Unknown or ambiguous anchors abort the build.
  - `profile.json`: weights profile name (`prot`).
- `tooling/build_variant.py <variant.json> [--passthrough] [--out]`: drop lines tagged only for other classes/races; strip untagged `[OC]` Gear/Loot lines; apply the overlay; insert generated gear lines after the matching `[QT]`; rewrite `[D ...]` prefix and footer/group; write the folder, both TOCs (Interface 16001) and the zip; write a report (drops, strips, overlay ops, "needs overlay" lines matching flag words: shaman, totem, Totemic, Brawler, Leatherworking, leather, hunter, pet, Rockbiter, Flametongue, Ghost Wolf, 2H, Int, Spirit). `--passthrough` must reproduce the Alliance chapters byte-identically (regression test).
- Gear generation: `weights/profiles.py` registry (`enh` wraps the existing shaman behaviour exactly; `prot` in `weights/prot_weights.py`). Prot usable: mail (4,3) any level, leather, cloth cloak only, shields (4,6), 1H axe/mace/sword/dagger/fist, ranged as a low-value pull slot; no 2H. Initial central weights: 1H dps 6, ranged dps 1, Str 2, AP 1, Sta 1.5, Agi 0.9, Armor 0.03/pt, Defense 1.5/pt, Block value 0.5, Block chance 3/%, Dodge/Parry 4/%, hit 6/%, crit 4/%, expertise 2/pt, Int/Spirit/spell 0; conservative: Sta 1.0, Defense 1.0, Armor 0.02. Documented as reasoning-only in `docs/forever-prot-stat-weights.md`. `score_items.parse()` extended with Armor, Defense ("Increased Defense + N"), Block value ("N Block"), block/dodge/parry chance, hit, crit, with existing output unchanged. `gear_calls.py --profile prot --variant ... --emit generated_gear.json` writes per-quest and per-dungeon picks in the guide's wording ("take |cff66ff66X|r (mail hands +5 Str +5 Sta, Def +3)", "nothing for a warrior - vendor", "X or Y, coin flip" within 10%); `dungeon_loot.py --profile prot` likewise. Missing tooltips listed, then fetched with `fetch_tooltips.py --from-file`.
- Tooling generalisation: `guidelib` reads the variant for FOOTER/CHAINS/RACE_WORDS when `FOREVER_GUIDE` names a variant's folder; `Warrior`, `Skyborne` added to RACE_WORDS; Zephras Isle (16593) added to ZONES/ZID and tarcheck's table; tarcheck/pool30 use `gl.ADDON`; the hook resolves the edited file's addon folder, uses per-folder baselines (`check_guide_baseline_<folder>.txt`, `verify_baseline_<folder>.txt`, Alliance names unchanged) and rebuilds a variant when a file under `tooling/variants/<v>/` changes; `hunter_score.py` pinned to the Alliance folder.
