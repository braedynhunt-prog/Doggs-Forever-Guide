# Druid variant: Phase 3 overlay spec (written 2 Nov 2026)

What the overlay for chapters 02-26 of `guide/Guidelime_ForeverDruid` must do, with the data behind each item. The overlay files `tooling/variants/skyborne_druid/overlay/<key>.txt` are byte-copies of the warrior overlay (`tooling/variants/skyborne_warrior/overlay/`): everything class-neutral in them stays (race-pair restores, Honor Students deletes, flight/tram restores, carry-over logs, `@gear-dungeon` anchors, Skinning + Mining text, Camping deletes); every warrior-specific operation is rewritten for a Skyborne feral druid or removed. Builder and syntax: `tooling/build_variant.py` (docstring) and `tooling/variants/skyborne_druid/README.txt`. Warrior spec (the model for this one, its global rules still apply where not overridden here): `docs/warrior-overlay-spec-2026-11-01.md`. Build record with every class fact: `docs/druid-build-2026-11-02.md`. Plan: `docs/druid-build-plan-2026-11-02.md`.

## How a block agent works
1. Read `docs/RULES.md`, `docs/druid-build-2026-11-02.md` ("Established facts" and "Travel"), this file, the warrior spec's "Global rules", the builder docstring and the variant README.
2. Emit is done (2 Nov): `tooling/variants/skyborne_druid/generated_gear.json` (feral picks for every `[QT]` with reward choices, 56 dungeon loot groups, 0 missing tooltips, 0 unstated). Do not re-run `--emit`.
3. Build to your own scratch folder, never `guide/`: `python tooling/build_variant.py tooling/variants/skyborne_druid/variant.json --out <scratch>/dry-<block>/Guidelime_ForeverDruid --report <scratch>/dry-<block>/build_report.txt`. The report's "Needs overlay", "Non-gear rewards", "Inline gear text" sections are a checklist; the main work list is the warrior-specific operations already in your overlay files (grep them for: warrior, Wu Shen, Kelv, Arias'ta, tank, Taunt, Defensive, Thunder Clap, Shield, Sunder, Charge, mana, 1698, 1699, 1702, 1681, 1682, 1665, 1666, 1667, Bartleby, Haggard, Dead-tooth, Tormus, @header).
4. For each chapter read the Alliance source, the current overlay, and the built output; rewrite; rebuild; re-read the built chapter end to end until it reads as a druid guide.
5. Checks on the build folder with `FOREVER_GUIDE` set to it: `check_guide.py` (0 flow problems except the documented cross-block carries), `tarcheck.py` (nothing new in your chapters), `verify.py --all` (nothing new in your chapters against the Alliance baseline). Every overlay line ASCII, LF.
